# P1 · Dueño: operación diaria y datos de pago

Implementa todo lo de este documento en un solo cambio. Son cuatro pantallas nuevas del **dueño** (Movimientos, Ajuste manual, Reclamaciones y Solicitudes de alta) y un cambio de seguridad en Membresía.

## 0. Reglas (valen para todo el documento)
- **No inventes rutas, campos ni códigos de error.** Usa exactamente los de aquí. Si necesitas uno que no esté, **pregúntamelo antes de programarlo**.
- Todo el texto en español de México. Fechas `AAAA-MM-DD` con `fechaCorta()` e instantes con `instante()` (`@/lib/api/formato`, hora de México). Dinero con `pesos()`.
- Toda acción que cambia datos pide confirmación con `AlertDialog`, con el botón deshabilitado mientras se envía.
- **403 `requiere_totp_reciente`**: envuelve la llamada con `useConTotp()` (ya existe, `src/components/totp-provider.tsx`).
- **402 `membresia_vencida`**: toast "Tu membresía está vencida: regulariza tu pago para hacer cambios", con enlace a `/negocio/membresia`.
- **429**: usa el texto que ya da `src/lib/api/errors.ts`. **401**: el `api()` actual ya lo resuelve.
- Nada de datos de clientes, bancarios ni de sesión en `localStorage` o `sessionStorage`.
- Móvil (400 px) y computadora; la barra inferior no debe tapar botones.
- Las pantallas nuevas usan `RequiereSesion` con `roles={["dueno"]}` y `SeccionNegocio` (`@/components/negocio/comun`), igual que `/negocio/marca`.

## 2. API (archivo nuevo `src/lib/api/operacion.ts`)
Respuestas **reales** de Barbería Demo (recortadas donde dice `…`).

### 2.1 Movimientos: `POST /api/historial/consulta`
Cuerpo (todo opcional): `{ desde, hasta, operador_persona_id, telefono, tipo, modulo, tarjeta_digital_id, limite, antes_de, antes_id }`.
- `desde`/`hasta`: jornadas `AAAA-MM-DD` (por omisión hoy; hasta **92** jornadas). `tipo`: `acumulacion | canje | ajuste_manual | expiracion | vencimiento | referido`. `modulo`: `monedero | tarjetas_sellos`. `limite` 1–100 (usa 50).
```json
{ "desde": "2026-10-06", "hasta": "2026-10-06", "zona_horaria": "America/Mexico_City",
  "siguiente": { "antes_de": "2026-10-06T21:53:43.519438+00:00", "antes_id": "4fca60ce-…" },
  "movimientos": [
    { "movimiento_id": "4fbced63-…", "fecha": "2026-10-06T22:47:23Z", "jornada": "2026-10-06", "modulo": "monedero", "tipo": "ajuste_manual",
      "monto_centavos": 1000, "saldo_resultante_centavos": 2271, "motivo": "Reclamación R-0001: Revisamos el ticket, gracias", "origen": "ajuste_manual",
      "cliente": { "nombre": "Diego", "apellido_paterno": "Demo", "apellido_materno": null, "telefono": "+525510000004" },
      "operador": { "persona_id": "…", "nombre": "Carla", "apellido_paterno": "Demo", "rol": "dueno" } },
    { "movimiento_id": "b3a09370-…", "fecha": "2026-10-06T21:53:53Z", "jornada": "2026-10-06", "modulo": "tarjetas_sellos", "tipo": "canje",
      "cantidad": -5, "tarjeta": "Cortes", "tarjeta_digital_id": "30000000-…", "motivo": "Canje de premio", "origen": "app",
      "cliente": { "nombre": "Diego", … }, "operador": { "persona_id": "…", "nombre": "Emilio", "apellido_paterno": "Prueba", "rol": "empleado" } }
  ] }
```
- Los campos sin valor **no vienen** (no llegan como `null`). `operador` puede ser `{ "nombre": "Staff MiSaldo", "rol": "staff" }` o `null` (= "Sistema").
- Errores: 404 `cliente_no_encontrado` (ese teléfono no es cliente); 400 `rango_invalido`, `fecha_futura`, `rango_excedido`.

### 2.2 Excel del historial
- Conteo: `POST /api/negocio/exportaciones/historial` con `{ desde, hasta }` y los mismos filtros de 2.1 (`operador` en lugar de `operador_persona_id`, `telefono`, `tipo`, `modulo`, `tarjeta_digital_id`) → real: `{ "conteo": 7, "tope": 20000, "excede_limite": false }`.
- Descarga: `POST /api/negocio/exportaciones/historial/descarga` con el mismo cuerpo → el archivo `.xlsx` (`Content-Disposition: attachment; filename="historial_2026-10-01_2026-10-06.xlsx"`). Exige **TOTP reciente** si el dueño tiene 2FA; **10 descargas por hora** (429).
- Agrega en `src/lib/api/client.ts` una función exportada **`apiArchivo(path, body)`** que haga lo mismo que `api()` (Bearer, `credentials: "include"`, un reintento tras `refrescar()` en 401, `ApiError` con el JSON del error) pero que devuelva `{ blob, nombre }` (el nombre sale de `Content-Disposition`). Guarda el archivo con un `<a download>` temporal.

### 2.3 Ajustes manuales
- `POST /api/ajustes/monedero` → `{ telefono, monto_centavos, motivo, idempotency_key }` (`monto_centavos` con signo, ≠ 0).
- `POST /api/ajustes/sellos` → `{ telefono, tarjeta_digital_id, cantidad, motivo, idempotency_key }` (`cantidad` con signo, −1000 a 1000, ≠ 0).
- `motivo` 5–500 (**el cliente lo recibe por WhatsApp**). `idempotency_key`: `nuevaLlave()` **una vez por operación**; si reintentas la misma (red caída, TOTP), manda la misma llave.
- **201** (aplicado) o **200** (reintento ya aplicado, `duplicado: true`):
```json
{ "resultado": "ok", "duplicado": false, "ajuste_id": "…", "solicitado": -5000, "aplicado": -2271, "topado": true, "alerta": false,
  "motivo": "…", "saldo_anterior_centavos": 2271, "saldo_centavos": 0,
  "aviso": "El cliente solo tenía {saldo anterior}; se ajustó {aplicado} y su saldo quedó en {saldo nuevo}." }
```
  `aviso` solo llega si `topado` es `true`, ya redactado por el backend: muéstralo tal cual. En sellos llegan además `tarjeta_nombre`, `tarjetas_completadas`, `tarjetas_reabiertas` y `tarjeta: { sellos_actuales, sellos_requeridos, fecha_vencimiento } | null`.
- Errores: 409 `tope_diario_excedido` (+ `disponible_hoy`), 409 `sin_configuracion`, 403 `autoajuste` ("No puedes ajustar tu propia cuenta de cliente"), 403 `modulo_inactivo`, 404 `cliente_no_encontrado` / `tarjeta_no_encontrada`, 400 `motivo_invalido` / `monto_invalido` / `cantidad_invalida`, 409 `idempotency_conflicto`.
- Límites: `GET` y `PUT /api/ajustes/configuracion`. Real: `{ "tope_diario_centavos": null, "tope_diario_sellos": null, "umbral_alerta_centavos": 50000, "umbral_alerta_sellos": 10 }`. El `PUT` manda **los cuatro** (`null` = apagado). 400 `valor_invalido`.

### 2.4 Reclamaciones
- Lista: `GET /api/reclamaciones?estado=pendiente&limite=50` (sin `estado` = todas; cursor `antes_de` + `antes_id`) → `{ reclamaciones: Reclamacion[], siguiente }`.
- Detalle: `GET /api/reclamaciones/{reclamacion_id}` → `{ reclamacion, historial }`. `historial` tiene la forma de 2.1: los movimientos del cliente del día anterior a la compra al siguiente.
- Aprobar: `POST /api/reclamaciones/{id}/aprobacion` con `{ cantidad?, nota? }` (por omisión, lo reclamado; nota ≤ 400, la lee el cliente). **TOTP reciente** con 2FA y 402 con membresía vencida. **Crea el ajuste**.
- Rechazar: `POST /api/reclamaciones/{id}/rechazo` con `{ nota }` (5–500, obligatoria).
- Cancelar (error de captura): `POST /api/reclamaciones/{id}/cancelacion` con `{ motivo }` (5–500). No avisa al cliente.
- Real (`Reclamacion`):
```json
{ "reclamacion_id": "dae19c50-…", "folio": "R-0001", "estado": "aprobada", "modulo": "monedero", "tarjeta": null,
  "cantidad_reclamada": 1000, "cantidad_aprobada": 1000, "fecha_compra": "2026-10-06", "referencia_ticket": null,
  "descripcion": "Pagó un corte de $200 y no se le sumó el saldo", "resolucion_nota": "Revisamos el ticket, gracias",
  "creado_en": "2026-10-06T21:54:05Z", "resuelto_en": "2026-10-06T22:47:23Z", "ajuste_id": "964c1d33-…",
  "cliente": { "nombre": "Diego", "apellido_paterno": "Demo", "apellido_materno": null, "telefono": "+525510000004" },
  "creado_por": { "persona_id": "…", "nombre": "Emilio", "apellido_paterno": "Prueba", "rol": "empleado" },
  "resuelto_por": { "persona_id": "…", "nombre": "Carla", "apellido_paterno": "Demo", "rol": "dueno" } }
```
  `cantidad_*`: centavos si `modulo` es `monedero`; sellos si es `tarjetas_sellos` (con `tarjeta: { tarjeta_digital_id, nombre }`).
- Errores: 409 `ya_resuelta` (recarga), 409 `cliente_inactivo` ("El cliente ya no está activo: recházala con una nota"), 409 `tarjeta_inactiva`, 409 `cliente_sin_telefono`, 409 `tope_diario_excedido`, 403 `autoajuste`, 404 `reclamacion_no_encontrada`, 400 `cantidad_invalida` / `nota_invalida`.

### 2.5 Solicitudes de alta
- Lista: `GET /api/validaciones-alta?estado=pendiente&limite=50` (sin `estado` = todas) → `{ validaciones: Validacion[] }`.
- Cancelar: `POST /api/validaciones-alta/{validacion_id}/cancelacion` con `{ motivo }` (5–500) → `Validacion`. 409 `ya_resuelta`, 404 `no_encontrada`.
- Real (`Validacion`):
```json
{ "validacion_id": "8e40f3b2-…", "tipo": "cliente", "estado": "confirmada", "resultado": "ok", "telefono": "+525510000002",
  "nombre_capturado": { "nombre": "Alberto", "apellido_paterno": "Gómez", "apellido_materno": null },
  "capturado_por": { "persona_id": "…", "nombre": "Emilio" },
  "creado_en": "2026-10-07T01:00:11Z", "expira_en": "2026-10-10T01:00:11Z", "resuelto_en": "2026-10-07T01:00:56Z", "motivo_cancelacion": null }
```
  `estado`: `pendiente | confirmada | rechazada | vencida | cancelada`.

## 3. Pantalla Movimientos (`/negocio/movimientos`)
- **Filtros** arriba (en el móvil, plegables bajo "Filtros"): Desde y Hasta (por omisión hoy; máximo 92 días), Tipo, Módulo (solo si el negocio tiene los dos), Tarjeta (las de `GET /api/negocio/configuracion` → `tarjetas`), Cajero (los de `GET /api/empleados`, más "Todos") y Teléfono del cliente (10 dígitos → `telefonoE164`). Acepta `?telefono=55…` en la URL para llegar desde la ficha del cliente.
- **Lista** (más reciente primero) con "Cargar más" usando `siguiente`. Cada fila:
  - título según `tipo` y `modulo`: "Ganó {pesos(monto)} (compra de {pesos})", "+{n} sello(s) en {tarjeta}" con el plural correcto, "Canjeó {pesos}", "Canjeó un premio de {tarjeta}", "Ajuste: {motivo}", "Venció {pesos o sellos}", "Premio por recomendar";
  - a la derecha, el monto o los sellos **con signo** (verde si suma, rojo si resta);
  - segunda línea: cliente (nombre y teléfono con `telefonoVisible`) · operador ("Sistema" si es `null`) · `instante(fecha)`.
- **Exportar a Excel**: botón que primero pide el conteo; si `excede_limite`, "Son más de 20,000 movimientos: reduce el rango"; si no, `AlertDialog` "¿Descargar {conteo} movimientos?" y la descarga con `conTotp`.
- Al final, la sección **"Límites de ajustes manuales"** (2.3): tope diario de saldo, tope diario de sellos, alerta desde (saldo) y alerta desde (sellos); cada uno con un interruptor "Sin límite" (= `null`). Guardar con `AlertDialog`.

## 4. Ajuste manual (desde la ficha del cliente)
En `/clientes`, en la ficha abierta, agrega tres botones:
- **"Ajustar saldo o sellos"**: abre un `Sheet` (móvil: desde abajo):
  1. Qué ajustar: "Saldo" (si hay `ficha.monedero`) o cada tarjeta **activa** de `ficha.tarjetas`.
  2. **Sumar / Restar** (dos botones grandes) y la cantidad (pesos con `aCentavos`, o sellos enteros 1–1000).
  3. **Motivo** (5–500) con la ayuda "El cliente lo recibe por WhatsApp".
  4. `AlertDialog`: "¿Restar $50.00 del saldo de Diego Demo?" / "¿Sumar 2 sellos a Cortes de Diego Demo?".
  5. Resultado (comprobante en el mismo `Sheet`): "Listo: {aplicado}". Saldo o tarjeta nuevos; si `topado`, muestra `aviso`; si `tarjetas_completadas > 0`, "Completó {n} tarjeta(s)"; si `tarjetas_reabiertas > 0`, "Se reabrieron {n} tarjeta(s)". Después recarga la ficha.
- **"Ver movimientos"** → `/negocio/movimientos?telefono={10 dígitos}`.
- **"Ver reclamaciones"** (solo si `resumen.reclamaciones_pendientes > 0`) → `/negocio/reclamaciones`.

## 5. Reclamaciones (`/negocio/reclamaciones`)
- Pestañas **Pendientes** (por omisión) y **Todas**. Fila: folio, chip de estado (Pendiente / Aprobada / Rechazada / Cancelada), cliente, lo reclamado ("$10.00 de saldo" o "2 sellos de Cortes"), "Compra del {fechaCorta(fecha_compra)}" y "Levantó: {creado_por.nombre}". "Cargar más" con `siguiente`.
- Al tocar una fila: `Sheet` con el detalle (2.4): descripción, ticket, fechas y, si está resuelta, quién, cuándo, cantidad aprobada y nota. Debajo, **"Movimientos alrededor de la compra"** con `historial.movimientos` (mismo formato de fila que Movimientos; si no hay: "No hay movimientos de ese día").
- Si está **pendiente**, tres acciones:
  - **Aprobar**: cantidad editable (por omisión la reclamada) y nota opcional (≤ 400). `AlertDialog` "¿Aprobar y abonar {cantidad} a {cliente}?". Con `conTotp`. Toast "Aprobada: se abonó {…} y le avisamos al cliente".
  - **Rechazar**: nota obligatoria (5–500) "El cliente la leerá". Toast "Rechazada".
  - **Cancelar por error de captura**: motivo (5–500). "No se le avisa al cliente".
- Tras cualquier acción, recarga la lista y el conteo de Negocio y del Panel.

## 7. Datos de pago en Membresía (`src/components/membresia.tsx`)
1. **Borra** las constantes `WHATSAPP_URL`, `CLABE`, `TITULAR` y `TARJETA_OXXO`. Ningún número de cuenta, tarjeta ni teléfono de pagos debe quedar en el código.
2. En `SeccionMembresia` consulta `GET /api/negocio/membresia/pago` (2.6), solo con `sesion.contexto.rol === "dueno"` (como hoy).
3. Transferencia: Institución = `banco`, CLABE = `clabe`, Beneficiario = `beneficiario`. OXXO: Número de tarjeta = `tarjeta` (ya viene en grupos de 4), Titular = `titular`. "Ya pagué, enviar comprobante": `href={whatsapp.enlace}` tal cual. Lo que llegue en `null` **no se muestra**.
4. Cargando: "Cargando los datos de pago…". Error: "No pudimos cargar los datos de pago." y "Intentar de nuevo". Si `transferencia` y `oxxo` son `null`: "Por ahora no hay datos de pago disponibles. Intenta más tarde."
5. "Pago con tarjeta · Mercado Pago · Próximamente" y los botones "Copiar" no cambian.
